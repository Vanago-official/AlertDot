# AlertDot

Android-застосунок, який показує маленьку кольорову точку поверх усіх застосунків:
🟢 відбій, 🟡 жовтий рівень, 🔴 тривога. При зміні стану програє звук.

Події приходять із Telegram-бота [AirAlert](https://github.com/Vanago-official/AirAlert):
застосунок читає його сповіщення. Телефон не опитує API у фоні, тому батарея майже не витрачається.

- Kotlin · Jetpack Compose (Material 3) · minSdk 29 · targetSdk 35
- Без мережевих бібліотек; `INTERNET` використовується лише для ручної кнопки «Оновити зараз»

## Можливості

- **Точка поверх екрана.** Для кожного рівня окремо налаштовуються видимість, положення, розмір,
  прозорість і колір. Якщо рівень прихований (наприклад, відбій), вікно оверлею повністю знімається.
- **Положення.** Сітка 3×3 (кути, середини сторін, центр) або **📷 камера**: точка стає центром на
  виріз камери за координатами від Android. Велика напівпрозора точка дає ефект кільця навколо камери.
  Зсуви дробові (крок 0.1–5 dp), є D-pad і введення числом.
- **Свої шаблони.** Положення, розмір і прозорість можна зберегти під назвою й застосувати до будь-якого рівня.
- **Звуки.** Звук грає лише при зміні стану, потоком будильника (`USAGE_ALARM`), тож його чути
  при вимкненому звуку дзвінка. Правило обирається від найконкретнішого до загального:
  тип + рівень, далі тільки тип, далі тільки рівень. Звук можна взяти системний, свій файл
  або вбудований м'який сигнал. Є вібрація, режими «один раз» і «по колу», тихі години та
  опційне обходження режиму «Не турбувати».
- **Ручна перевірка.** Кнопка «🔄 Оновити зараз» один раз запитує alerts.in.ua.
- **Симуляція подій** для перевірки без бота.
- Інтерфейс українською, темна тема за замовчуванням.

## Як це працює

```
AirAlert-бот ──Telegram──▶ сповіщення ──▶ TelegramNotificationListener
                                              │
                         RuleBasedAlertParser │  "🔴 Red level — missile, drone threat"
                                              ▼
 ApiAlertSource (кнопка) ─▶ AlertEngine ◀── SimulatedSource
                              │  стан змінився?
                    ┌─────────┴─────────┐
                    ▼                   ▼
             DataStore (стан)    AlertSoundPlayer
                    │
                    ▼
             OverlayService ─▶ точка поверх екрана
```

Бот пише один рядок лише при зміні рівня:

```
🔴 Red level — missile, drone threat
🟡 Yellow level — guided bomb, drone threat
🚨 Alert — artillery threat
🟢 All clear
```

Типові правила розпізнавання (редагуються в застосунку: «Джерело» → «Розширені»):

| Рівень   | Ключові слова                 |
|----------|-------------------------------|
| Зелений  | `All clear`, `🟢`             |
| Жовтий   | `Yellow level`, `🟡`          |
| Червоний | `Red level`, `🔴`, `🚨`       |

`🚨 Alert` (тривога без рівня в API, наприклад артобстріл) вважається червоним.
Тип загрози визначається за першим словом зі списку, від найнебезпечнішого:
`nuclear`, `chemical`, `missile`, `guided bomb`, `aviation`, `drone`, `artillery`,
`urban combat`, `air raid`.

## Збірка

Потрібні JDK 17–21 і Android SDK (`platforms;android-35`, `build-tools;35.0.0`).
Gradle 8.11 не запускається на новіших JDK. Якщо системний JDK новіший, вкажіть потрібний
у `~/.gradle/gradle.properties`:

```properties
org.gradle.java.home=/path/to/jdk-21
```

Шлях до SDK вказується в `local.properties` (файл не комітиться):

```properties
sdk.dir=/home/you/Android/Sdk
```

```bash
./gradlew assembleDebug        # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # юніт-тести
./gradlew lintDebug            # lint
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Перший запуск

Головний екран показує чекліст «Підготовка». Що в ньому:

1. **Показ поверх інших застосунків**: дозволити для AlertDot.
2. **Доступ до сповіщень**: увімкнути AlertDot. Якщо Android пише **«Restricted setting»**
   (APK встановлено не з магазину), відкрийте Налаштування → Застосунки → AlertDot → **⋮** →
   **Allow restricted settings**, потім повторіть.
3. **Батарея**: дозволити роботу без оптимізації, а також Застосунки → AlertDot → Батарея → **Unrestricted**.
4. **Samsung (One UI)**: Догляд за пристроєм → Батарея → Обмеження фонового використання →
   **Never sleeping apps** → додати AlertDot. Інакше система може вимкнути слухача сповіщень.
5. **Сповіщення** (Android 13+): потрібні для кнопки «Зупинити», коли звук грає по колу.
6. **Назва бота** («Джерело»): як у заголовку сповіщення Telegram, наприклад `AirAlert`.
   У Telegram для цього чату має бути ввімкнений показ тексту повідомлень, а сам чат не має бути вимкнений.

Далі ввімкніть «Кружечок на екрані» і перевірте все через «🧪 Перевірка».

### Ручна перевірка через API (опційно)

«Джерело» → «Ручна перевірка через API»:
- **Токен alerts.in.ua**: той самий, що `ALARM` у `.env` бота. Зберігається лише на телефоні
  (`allowBackup=false`) і не вшивається в APK.
- **Місто / громада**: точно як `location_title` в API (як `CITY` у `config.cfg` бота).

Застосунок будує з відповіді API такий самий рядок, як бот (`alarm.py` → `level_line`),
і пропускає його через ті самі правила розпізнавання.

## Структура

```
app/src/main/java/com/vanago/alertdot/
├── AlertDotApp.kt        # граф залежностей, запуск AlertEngine
├── domain/               # чистий Kotlin, покритий тестами
│   ├── AlertParser.kt        # AlertParser, RuleBasedAlertParser, ChatFilter
│   ├── AlertSource.kt        # інтерфейс джерела подій (Telegram / API / симуляція / ntfy, FCM у майбутньому)
│   ├── AlertStateMachine.kt  # зміна стану → який звук грати
│   ├── ApiAlertMapper.kt     # відповідь alerts.in.ua → рядок бота
│   ├── Models.kt
│   └── Sound.kt              # SoundRule, вибір правила, тихі години
├── data/                 # налаштування й стан у DataStore (JSON), міграції
├── service/              # NotificationListener, OverlayService, AlertEngine, звук, receivers
└── ui/                   # Compose-екрани: Головна, Джерело, Кружечок, Звуки
tools/gen_sounds.py       # генерує вбудовані м'які сигнали в res/raw
```

### Нове джерело подій

Реалізуйте `domain.AlertSource` (потік `AlertEvent`) і додайте екземпляр у список `sources`
в `AlertDotApp`. Для текстових джерел підходить `RuleBasedAlertParser`.
